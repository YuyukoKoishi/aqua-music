| 项目 | 内容 |
|---|---|
| 文档版本 | v1.1 |
| 日期 | 2026-11-19 |
| 状态 | 待评审 |
| 前置项目 | AnyListen 歌曲下载扩展 `lx-api-source-downloader`（v0.1.0，已封存） |

> v1.1 变更（2026-11-19）：
> 1. 放弃 mpv 播放后端，改为浏览器 `<audio>` 播放（Chromium 原生支持 FLAC），服务端仅保留音频流代理（应对防盗链/CORS 直链）。
> 2. 搜索来源确定为移植 lx-music-desktop 内置五平台搜索接口（wy/tx/kg/kw/mg）到本地 Node 服务，不依赖外部搜索 API；聚合 API（gdstudio）降级为可选兜底源。

---

## 1. 背景与动机

前期项目（AnyListen 下载扩展，一期至三期）验证了 LX 音源脚本驱动的搜索与下载链路，但受限于 AnyListen 扩展沙箱：

1. 扩展无 UI 注入能力，右键菜单/按钮均不可行，仅命令面板可用。
2. 插件间无法互调资源，必须 fork 持有音源。
3. IPC 数据上限 10 MB，无损 flac 经宿主对话框落盘存在撞限风险。
4. 搜索数据源受限（公开聚合 API 仅 netease 稳定可用），多平台搜索无法在沙箱内实现。

结论：改为**独立于 AnyListen 的本地应用**——Node 本地服务 + 浏览器界面，自带 LX 音源脚本运行器、多平台搜索、播放与下载管理。AnyListen 扩展仓库封存于 v0.1.0，不再演进。

## 2. 目标与非目标

### 2.1 目标

1. **替代 AnyListen 日常听歌**：完整媒体播放功能（播放/暂停/上下曲/进度/音量/播放模式）。
2. 多平台搜索（wy/tx/kg/kw/mg），结果按字符契合度排序。
3. 歌词显示：LRC 解析，滚动字幕，与播放进度对齐。
4. 歌单管理（自建歌单、收藏）与播放历史，本地持久化。
5. 下载管理器：批量下载、队列（暂停/继续/重排）、下载历史，自定义下载路径与文件名模板，本地持久化。
6. 音源必须经由 LX 音源脚本（不得绕过 LX 直接用第三方直链）。
7. 音质选择与降级链（128k → 192k → 320k → wav → flac → flac24bit → dolby → master，与脚本声明取交集）。
8. 支持多轮迭代测试，稳定可用后发布。

### 2.2 非目标

1. 不做托盘常驻、系统通知、开机自启、静默运行——用户已明确不需要。
2. 不修改、不依赖 AnyListen。
3. 不做在线账号体系；全部数据存本地。
4. 不做移动端适配（桌面浏览器优先）。
5. 不做本地音频文件库管理（只管在线内容与下载产物）。

## 3. 已确认的关键决策

| 编号 | 决策项 | 结论 | 说明 |
|---|---|---|---|
| D1 | 项目载体 | 独立新仓库 `aqua-music`，与 AnyListen 零依赖 | 与插件项目性质完全不同，分仓开发 |
| D2 | 界面形态 | 浏览器网页（方案 B） | 本地服务起 HTTP，浏览器打开管理页；不要托盘 |
| D3 | 播放后端 | **浏览器 `<audio>` 播放（v1.1 改定，放弃 mpv）** | Chromium 原生支持 FLAC；服务端提供音频流代理，处理直链防盗链（Referer/UA）与 CORS；进度用 `currentTime` 对齐歌词，Media Session 天然可用 |
| D4 | 歌词显示 | 网页滚动字幕，按播放时间对齐 | 前端直接读 `audio.currentTime` 对齐 LRC 时间戳，无需服务端进度推送 |
| D5 | LX 脚本运行 | 自研运行器：Node `vm` + request shim + crypto 工具集 | 参考 lx-music-desktop 与 lx-web-music 实现 |
| D6 | 搜索范围与来源 | wy/tx/kg/kw/mg 全平台；**移植 lx-music-desktop 内置平台搜索接口到本地服务**（v1.1 改定） | LX 音源脚本无 search 动作（仅 musicUrl/lyric/pic）；平台搜索为 LX 客户端内置公开接口，本地服务直连无 CORS 问题；聚合 API（gdstudio/Meting）仅作可选降级源 |
| D7 | 结果排序 | 字符契合度多级匹配（移植三期 `rankCandidates` 思路） | name+artist 归一化比对，NFKC，多歌手支持 |
| D8 | 持久化 | JSON 文件本地存储 | 歌单、播放历史、下载历史均持久化（用户 2026-11-19 明确两项历史都要） |
| D9 | 服务地址 | 默认 `127.0.0.1:9528`，端口占用自动顺延 | 启动时打印实际地址 |
| D10 | 前端栈 | Vue 3 + Vite | 无 SSR；构建产物由 Node 服务静态托管 |
| D11 | 下载实现 | 服务端直接 fetch 音频流写磁盘 | 不经浏览器，无 IPC 上限问题 |
| D12 | 封面/元数据 | 复用一期策略：聚合 API 直取 `pic_id`，300 KB 上限 | 缺失跳过不阻塞 |
| D13 | 歌词来源 | LX 脚本 lyric 动作优先，聚合 API 降级 | 与音源解耦的兜底 |
| D14 | 文件命名模板 | 可配置，默认 `{歌手} - {歌名}` | 支持 {歌名}/{歌手}/{专辑}/{音质} 变量 |

## 4. 系统架构

```
浏览器 (Vue 3 SPA)
  │  HTTP；下载进度用 SSE/WebSocket
  │  播放：<audio> 直接或经本地代理流加载
  ▼
Node 本地服务 (TypeScript)
  ├─ 搜索模块   → 内置五平台搜索适配（移植 lx-music-desktop）
  │               → 聚合 API 可选降级
  ├─ LX 运行器  → vm 沙箱跑 wy/tx/kg/kw/mg 脚本（musicUrl/lyric/pic）
  ├─ 音频代理   → fetch 音源直链，透传 Referer/UA，流式转发给浏览器
  ├─ 下载管理   → 队列调度 → fetch 音频流 → 写磁盘
  └─ 持久化     → JSON 文件（歌单/播放历史/下载历史/设置）
```

### 4.1 播放链路（v1.1）

1. 前端请求取链：服务端经 LX 脚本 `musicUrl` 拿到直链 + 音质降级链。
2. 直链可用性校验（HEAD 探测）后返回给前端。
3. 浏览器 `<audio>` 播放：直链无防盗链则直接加载；有 Referer/UA 校验或 CORS 受限时走本地代理流（`/stream` 端点，服务端 fetch 后流式转发）。
4. 进度、歌词对齐、Media Session 全部在前端完成，不依赖服务端推送。

### 4.2 LX 脚本运行器

脚本来源与一期/三期一致（用户提供 LX 音源脚本）。运行器职责：

1. 解析脚本 `inited` 回调声明的 `sources` 与 `supportQualitys`。
2. 提供 `request` shim（服务端 fetch 代理，含 cookie/UA 头透传）。
3. 提供 crypto 工具集（与 lx-music-desktop 环境约定一致：aesDes、md5、rsa 等）。
4. `musicUrl` / `lyric` / `pic` 动作调用与超时重试。

### 4.3 搜索适配（v1.1 新增）

五平台搜索适配层移植自 lx-music-desktop 客户端内置实现（公开网页端接口，无需账号）。接口失效风险与社区惯例：listen1/LX 社区均随平台改版更新适配，本项目跟进同样的维护方式。聚合 API（gdstudio）作为平台接口整体失效时的可选兜底，默认关闭亦可。

### 4.4 参考项目

- [lx-web-music](https://github.com/linjioujiou/lx-web-music)：LX 音源协议网页播放器，多平台搜索/播放列表/音质降级/歌词，架构参考。
- lx-music-desktop：LX 脚本环境约定与内置平台搜索接口的权威实现。
- [CyberryRe/lx_music-for-dsh](https://github.com/CyberryRe/lx_music-for-dsh)：同构架构先例（内置五平台搜索 SDK + 音源脚本引擎）。

## 5. 功能需求

### FR-1 搜索
1. 关键词搜索，可选平台（全部/单选），分页。
2. 结果含 歌名/歌手/专辑/时长/音源标识；按字符契合度排序。
3. 搜索失败降级（内置平台适配 → 聚合 API 可选兜底），全程重试与错误提示。

### FR-2 播放
1. 播放/暂停/上一曲/下一曲/进度拖动/音量。
2. 播放模式：顺序、单曲循环、列表循环、随机。
3. 点击搜索结果或歌单曲目即播；入队当前播放列表。
4. 音质偏好设置，播放失败逐级降级并如实反馈实际音质。
5. Media Session 集成（浏览器锁屏控制，尽力而为）。

### FR-3 歌词
1. LRC 解析（含翻译行可选显示）。
2. 滚动字幕：当前行居中/高亮，随 `audio.currentTime` 自动滚动，用户拖动进度后立即重对齐。
3. 无歌词时显示占位，不阻塞播放。

### FR-4 歌单与历史
1. 自建歌单：增删歌单、增删曲目、排序。
2. 收藏（我喜欢）为内置歌单。
3. 播放历史：记录时间/来源/音源，可清空。
4. 全部持久化到本地 JSON，重启恢复。

### FR-5 下载
1. 单曲/批量（多选、整张歌单）加入下载队列。
2. 队列：暂停/继续/取消/重排/失败重试；并发数可配置。
3. 下载历史：文件名/路径/音质/完成时间/状态，可清空。
4. 保存路径与命名模板可配置；重名策略（跳过/覆盖/自动加序号）。
5. 元数据写入（标题/歌手/专辑/封面），封面 300 KB 上限。
6. 歌词内嵌开关（LRC 嵌入，默认关）。

### FR-6 设置
音源脚本管理（导入/启用/禁用）、音质偏好、下载路径、命名模板、重名策略、并发数、聚合 API 兜底开关。

## 6. 验收标准

1. 搜索 wy/tx/kg/kw/mg 均可返回结果且排序合理。
2. 浏览器播放 flac 无损成功（Chromium 原生支持）；防盗链直链经本地代理流播放成功。
3. 歌词滚动与音频对齐，误差无感知（±500ms 内）。
4. 歌单/历史/设置重启后完整恢复。
5. 批量下载 10 首 flac 全部落盘成功，文件名符合模板，元数据齐全。
6. 断网/音源失效时有明确错误提示，不崩溃。

## 7. 里程碑

- M1 骨架：服务启动、Web UI 雏形、设置持久化。
- M2 搜索（五平台内置适配）+ LX 运行器。
- M3 播放（<audio> + 音频代理流）+ 歌词。
- M4 歌单/历史持久化。
- M5 下载管理器。
- M6 打磨、打包发布（zip 单目录，含启动脚本）。
