# 开发计划：aqua-music（本地网络音乐播放器）

配套 PRD：`PRD-music-player.md`（v1.1）。开发在新会话、新仓库进行。

> v1.1 变更（2026-11-19）：
> 1. 播放改浏览器 `<audio>`（放弃 mpv）：删去 mpv 进程管理/IPC/进度轮询任务，新增音频流代理与前端播放器任务。
> 2. 搜索来源改定为移植 lx-music-desktop 内置五平台接口；聚合 API 降级为可选兜底。

## 阶段 0：项目初始化（M1 前置）

- [x] 0.1 新建仓库与目录骨架（仓库名 `aqua-music`；工作目录 `D:/File/aqua-music/`）
- [x] 0.2 技术栈落地：Node + TypeScript（服务端）、Vue 3 + Vite（前端）、pnpm
- [x] 0.3 服务骨架：HTTP 服务、静态托管前端产物、端口探测（默认 9528，占用顺延）
- [x] 0.4 CI/脚本：dev/build/test 命令；测试框架沿用 `node --test`（纯模块约定，跨模块显式 `.ts` 后缀）

## 阶段 1：设置与持久化基座

- [x] 1.1 JSON 存储层（读写原子性、损坏兜底）

## 阶段 2：LX 运行器 + 搜索（M2）

- [x] 2.1 vm 运行器：加载脚本、`inited` 回调解析 `sources`/`supportQualitys`
- [x] 2.2 request shim：fetch 代理、header/cookie 透传、超时
- [x] 2.3 crypto 工具集（对齐 lx-music-desktop 约定）
- [x] 2.4 `musicUrl` 动作：音质降级链 + 多脚本重试 + URL 校验
- [x] 2.5 内置五平台搜索适配（移植 lx-music-desktop：wy/tx/kg/kw/mg 公开接口，统一结果模型）；聚合 API 可选兜底接入
- [x] 2.6 字符契合度排序（移植三期 `rankCandidates`：NFKC、多歌手、版本词过滤）
- [x] 2.7 单测：运行器、平台适配（响应解析用录制样本，不发真实请求）、排序
- [x] 2.8 集成测试：真实脚本跑通 wy 取链；五平台真实搜索各一轮

## 阶段 3：播放（M3）

- [x] 3.1 取链播放 API：`musicUrl` 取直链 → HEAD 可用性校验 → 返回直链或代理标记
- [x] 3.2 音频流代理端点：服务端 fetch 直链（Referer/UA 透传）→ 流式转发，支持 Range
- [x] 3.3 播放列表内存模型：当前队列、上下曲、播放模式（顺序/单曲/列表循环/随机）
- [x] 3.4 前端 `<audio>` 播放器：控制条/进度/音量/队列侧栏/播放模式；降级重试（换音质/换源）
- [x] 3.5 歌词：LRC 解析（含翻译）、`lyric` 动作 + 聚合 API 降级
- [x] 3.6 前端歌词滚动字幕：按 `audio.currentTime` 对齐、拖动重对齐、无词占位
- [ ] 3.7 Media Session 集成
- [ ] 3.8 测试：代理端点单测（Range/头透传）；浏览器实测 flac 直连与代理两条路

## 约定

- 每个开发步骤完成后必须有对应测试验证可用性（单测/集成/实测），测试通过才算该步骤完成

- 主程序/宿主：无（不再依赖 AnyListen；禁止引入对 `app.asar` 的任何依赖）
- 插件仓库 `anylisten-downloader` 封存于 v0.1.0，仅允许 README 加迁移说明
- 文档与提交保持正常语域；沟通可用 caveman 风格
- 每阶段完成即 commit，多轮测试后再进下一阶段（沿用既有流程）
